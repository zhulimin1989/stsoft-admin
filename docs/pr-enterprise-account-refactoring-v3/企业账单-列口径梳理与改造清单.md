## §1 两个前置概念（先分清，后面不混）

| 概念 | 是什么 | 什么时候发生 |
| --- | --- | --- |
| **代金券扣费**（用券） | 客户消耗时用手里的券抵扣，是平台授予 credit 的消耗 | 消费发生的当下 |
| **发券金额**（发券） | 当期账单多收后，平台补给客户一张券 | 对账发现差异之后 |

发券 ≠ 用券，两者永不混用：**发券只冲减应收金额，不参与待付款计算**（补偿在发券时已通过券资产完成，若再压待付款等于重复补偿）；用券是结算通道之一，影响扣费金额。

---

## §2 通用勾稽（两类客户共用一套公式）

```
扣费金额   = 消耗金额 − 代金券扣费
应收金额   = 消耗金额 + 调整金额 − 发券金额      ← 全口径总账（收入视角），发券只冲减它
已付款金额 = 现金支付（预付款用户：余额扣减；授信用户：核销回款）
待付款金额 = max(0, 扣费金额 + 调整金额 − 已付款金额)   ← 发券不参与，恒 ≥ 0
```

资金扣减优先级：**代金券 → 余额 → 信用额度**。

三个金额各答一个问题：**应收** = 这期真实总账（收入视角，发券补偿只在这里体现）；**已付款** = 真金白银收了多少；**待付款** = 扣费口径下还差多少现金（只由扣费、调整、已付决定，与发券无关）。补偿发券且结清后存在自证关系：（已付款 + 代金券扣费）− 应收 = 发券金额，账单行可自行解释资金去向。

## §3 每一列的意义（分客户类型）

### 3.1 基础信息列（两类客户完全相同）

| 列 | 含义 |
| --- | --- |
| 企业名称 / 账单月份 | 账单归属：一个企业 × 一个自然月 |
| 请求数 / token 总量 | 当期用量统计 |
| 剩余账期 | 距账期截止的天数，结清后显示"—" |
| 状态 | 待核销 / 已核销（有过回款动作即已核销） |
| 账期截止时间 | 精确到秒，延期过附「已延期」标记 |
| 操作 | 核销 / 账单调整 / **补偿发券（新增）** / 延期 / 下载账单 |

### 3.2 金额列 · 预付款用户视角

预付款用户先充钱后消费，**消耗发生时钱就从余额里实时扣掉了**，所以账单对它来说更像"消费流水账 + 对账凭证"。

| 列 | 对预付款用户的意义 |
| --- | --- |
| 消耗金额 | 当月折后总消耗，月末定格 |
| 代金券扣费 | 消耗中走券的部分（有券优先烧券） |
| 扣费金额 | 消耗 − 券 = 真正从余额里扣的部分 |
| 调整金额 | 对账发现差异（折扣生效晚、计数差异）时的修正累计 |
| 发券金额 | 当月多扣了客户钱时，以券形式退回的补偿 |
| 应收金额 | 这期客户总共该承担多少（含券的全口径） |
| 已付款金额 | 从余额里实际扣掉的金额。**正常情况下 = 扣费金额**（余额够扣，月月自动结清） |
| 待付款金额 | **正常恒为 0**。唯一例外：余额耗尽的最后一次调用产生一笔未结算金额 |

> 预付款用户的核销按钮基本用不到（待付款恒 0 → 自动置灰），账单调整和补偿发券才是它的常用操作。

### 3.3 金额列 · 授信用户视角

授信用户先消费后回款（Net-30），**消耗挂信用，回款靠核销**，账单是它的"应收账款台账"。

| 列 | 对授信用户的意义 |
| --- | --- |
| 消耗金额 | 当月折后总消耗，月末定格 |
| 代金券扣费 | 消耗中走券的部分 |
| 扣费金额 | 消耗 − 券 = 挂在信用上的部分 |
| 调整金额 | 对账差异修正（同预付款） |
| 发券金额 | 客户已付清后发现多收，补券冲减应收 |
| 应收金额 | 这期客户总共该付多少（全口径，催收基准） |
| 已付款金额 | 客户实际回款、运营核销的累计。**未回款时为 0** |
| 待付款金额 | **核心催收指标**：这期还差多少钱没回。账期截止未清零 → 授信失效 |

> 授信用户的核销是核心操作：核销成功 → 已付款+、待付款−，同时用户侧余额+、已用信用−、可用信用恢复。

### 3.4 一列差异速查

| 列 | 预付款用户 | 授信用户 |
| --- | --- | --- |
| 已付款金额 | 余额实时扣减，通常 = 扣费金额 | 核销回款累计，未回款 = 0 |
| 待付款金额 | 恒 0（余额耗尽最后一笔除外） | 催收抓手，账期内必须清零 |
| 核销按钮 | 基本不用（置灰） | 核心操作 |
| 账期/状态列 | 基本无感 | Net-30 管理主线 |

## §4 HTML 演示稿改动清单

1. **新增「发券金额」列**（插在调整金额之后）
2. **应收金额按新公式重算**（= 消耗 + 调整 − 发券）：
3. **待付款公式改为 max(0, 扣费金额 + 调整金额 − 已付款金额)**（发券不参与）：已验算，6 行现有数字全部不变
4. **行内新增「补偿发券」按钮 + 弹窗**：
   - 只读带出：企业名称、账单月份、已付款金额、应收金额
   - 输入：补偿金额（> 0、精确到分、**≤ 已付款金额**）、补偿原因（必填）
   - 预览：应收金额 X → Y
   - 确认后：发券金额 +=、应收 −=、待付款重算（保持 ≥ 0）
5. 核销弹窗、账单调整弹窗、延期弹窗**不变**
6. 列索引顺移（操作列 14 → 15），JS 里所有 tds 引用同步更新

7. 账单调整弹窗 · 调整后预览逻辑：账单调整会同时改变「应收金额」与「待付款金额」，且在未触达待付款下限时两者同幅变动。口径与 §2 一致：应收金额 = 消耗金额 + 调整金额 − 发券金额；待付款金额 = max(0, 扣费金额 + 调整金额 − 已付款金额)（发券不参与）。调整动作只改变调整金额本身，消耗金额、代金券扣费、已付款金额、发券金额均不变。预览展示格式：「应收金额 X → Y，待付款金额 A → B」，其中待付款预览值下限为 0（不为负）。示例：调增 ¥100.00 时，预览显示「应收金额 ¥3,500.00 → ¥3,600.00，待付款金额 ¥3,280.50 → ¥3,380.50」。
