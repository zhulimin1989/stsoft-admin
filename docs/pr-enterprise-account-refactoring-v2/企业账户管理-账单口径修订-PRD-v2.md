## §1 企业账单页

按自然月生成账单，一行 = 一个企业 × 一个自然月。

### 1.1 列表字段

| 字段 | 说明 |
| --- | --- |
| 企业名称、账单月份 | 账单归属 |
| 请求数、token 总量 | 当期用量 |
| 消耗金额 | 当期折后消耗 |
| 代金券扣费 | 当期消耗中由代金券抵扣的部分 |
| 扣费金额 | = 消耗金额 − 代金券扣费 |
| 应收金额 | = 扣费金额 |
| 调整金额 | 「账单调整」的累计金额，调减为负（红色展示） |
| 已付款金额 | 该账单已累计支付的金额 |
| 待付款金额 | = 应收金额 − 已付款金额 + 调整金额；为 0 时标红 |
| 剩余账期 | 距账期截止的天数 |
| 状态 | 待核销 / 已核销 |
| 账期截止时间 | 精确到秒，延期过的附「已延期」标记 |
| 操作 | 核销 / 账单调整 / 延期 / 下载账单 |

资金扣减优先级：**代金券 → 余额 → 信用额度**。

### 1.2 定格规则

自然月结束、账单生成后，消耗金额、代金券扣费、扣费金额、应收金额即定格，不再变化。之后只有三个字段会因操作变动：**调整金额**（账单调整）、**已付款金额**（核销）、**待付款金额**（由前两者推导）。

## §2 核销

核销 = 运营确认客户回款，核销金额计入该账单的已付款金额。

**操作规则**

- 入口：行内「核销」按钮；
- 金额必填、精确到分、必须 > 0，且**不超过该行待付款金额**；
- 待付款金额为 0 时按钮置灰；后续调增使待付款重新变正时按钮自动恢复。

**核销成功后的联动**

| 位置 | 变动 |
| --- | --- |
| 账单行 | 已付款金额 += 核销金额，待付款金额 −= 核销金额 |
| 用户侧 | 余额 += 核销金额；已用信用 −=、可用信用 += 核销金额 |

## §3 账单调整

账单出账后，客户确认金额与平台应收金额不一致时（如折扣生效日晚于出账、token 计数差异），运营通过账单调整修正。**调整只改「调整金额」列，应收金额不变。**

**操作规则**

- 入口：行内「账单调整」按钮；
- 弹窗内只读带出：企业名称、账单月份、消耗金额、已调整金额、应收金额、待付款金额；
- 方向单选：调增 / 调减，金额恒填正数，调减记负值；
- **调减校验：调减后待付款金额不可为负**（即调减金额 ≤ 当前待付款），超限拦截提示；
- 调增无上限；待付款为 0 的账单也允许调增，调增后待付款变正、核销按钮恢复；
- 调整原因必填。

**调整成功后的联动（以调减为例，调增反向）**

| 位置 | 变动 |
| --- | --- |
| 账单行 | 调整金额 −= 金额，待付款金额 −= 金额，应收金额不变 |
| 用户侧 | 余额 += 金额；已用信用 −=、可用信用 += 金额 |

**与发券的分工（互斥）**

- 平台多算、客户**尚未付清** → 走账单调整-调减，压减待付款；
- 平台多算、客户**已付清** → 不动账单，给客户**发放代金券**，在后续消耗中优先抵扣。

**报表体现**

每笔账单调整同步体现在：财务中心 → 财务报表 → 按量买赠 → 账户变动明细的「其他变动金额」列（与当前「调整余额」的对应关系不变）。

## §4 对账 Excel 模板

模板：`2026-XX- XX公司-账单.v2.xlsx`，三个 sheet：

| Sheet | 内容 |
| --- | --- |
| 账单汇总 | 按账号汇总：用量、目录总价、折后金额、折扣、占比；底部三行：合计（消耗金额）→ 代金券扣费 → 应收金额 |
| 产品模型汇总 | 按模型汇总：用量、目录总价、折后金额、折扣、占比 |
| 账单明细 | 行级明细：账期（自然日）、账户 ID、模型、类型、用量、目录价格、单价单位、折扣比、币种、总消耗金额、信用支付金额、代金券抵扣金额、已付款金额、待付款金额、结算状态 |

**明细行勾稽**：总消耗金额 = 信用支付金额 + 代金券抵扣金额 + 已付款金额 + 待付款金额（一行消耗按资金渠道拆分）。

**两类客户的明细差异**

| 客户类型 | 明细特征 |
| --- | --- |
| 授信用户 | 涉及信用支付金额、代金券抵扣金额、待付款金额、结算状态；没有充值时「已付款金额」列为 0 |
| 预充值用户 | 不涉及信用支付（信用支付金额 = 0）；正常情况下已付款金额 = 总消耗金额（从充值余额扣除），结算状态为「已结算」；仅余额耗尽时最后一次调用可能产生一笔「未结算」金额 |

两类客户都以**代金券优先抵扣**计算。

**导出与定格**：对账单在自然月结束后、对账时导出，导出即定格，之后不再修改；对账差异通过后台「账单调整」处理，结果体现在后台账单列表和财务报表，不回写对账单。

## §5 演示验证（2026-09-08）

基于演示稿自动化回归（8 月行：扣费 5,420.00 / 调整 −1,200.00 / 已付 2,000.00 / 待付款 2,220.00）：

- 调减 1,000 → 应收不变、调整 −2,200.00、待付款 1,220.00 ✅
- 调减超过待付款 → 拦截「调减后待付款金额不可为负」✅
- 核销 1,220 → 已付 3,220.00、待付款 0、核销按钮置灰 ✅
- 清账后调增 500 → 应收不变、待付款 500.00、核销按钮恢复 ✅
